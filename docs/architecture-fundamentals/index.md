# Architecture fundamentals

This section is the foundation of the whole repository. It teaches how to think like an architect
before teaching any specific technology: how to turn a business problem into requirements, how to
reason about quality attributes and trade-offs, how to communicate a design so others can build and
review it, and how to record decisions so they survive the people who made them.

If you are new to architecture, read these pages in order. If you already build systems, use them to
sharpen the vocabulary you use when you defend a design.

## What you will learn here

- Explain what a Solutions Architect does and does not do, and how the role differs from adjacent roles
- Separate functional requirements from non-functional requirements and write both so they can be tested
- Name the major quality attributes, see how they conflict, and make trade-offs explicit
- Draw and read C4 context, container, and component diagrams
- Write Architecture Decision Records (ADRs) and defend a decision in a review

**Prerequisites:** None. Start here.
